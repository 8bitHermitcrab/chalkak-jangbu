# 찰칵장부 📸🧾

> 거래명세서·영수증을 **찍기만 하면**, AI가 읽어서 **회계 처리(분개)**를 하고 **엑셀**로 정리해 주는 웹 서비스

FastAPI · Vue 3 · PostgreSQL · Docker · Claude Vision · Tesseract OCR

---

## 왜 만들었나

고깃집에서 일할 때, 정육점·채소 가게·주류 도매상에서 물건이 들어올 때마다 **거래명세서**를 받았습니다.
종이는 잃어버리기 쉬워서 받자마자 휴대폰으로 사진을 찍어 두었고, 영업이 끝나면 그 사진을 하나씩 넘기면서
**엑셀에 날짜, 거래처, 품목, 수량, 단가, 금액을 한 줄씩 손으로 옮겨 적었습니다.**

그 일을 하면서 느낀 불편함은 이랬습니다.

| 그때 불편했던 점 | 찰칵장부가 바꾼 점 |
| --- | --- |
| 사진을 찍었는데도 결국 **같은 내용을 엑셀에 한 번 더 입력**해야 했다 | 사진을 올리면 AI가 **거래처·일자·품목·금액을 바로 읽어** 칸을 채운다 |
| 사진 앨범과 엑셀 창을 오가며 **눈으로 대조**해야 했다 | 검토 화면에서 **원본 사진과 입력 칸을 나란히** 보고 틀린 칸만 고친다 |
| 손으로 옮기다 보면 **숫자를 잘못 치거나**, 수량×단가 계산이 틀려도 몰랐다 | 수량×단가 ≠ 금액, 공급가액+세액 ≠ 합계면 **바로 경고**하고, 금액이 안 맞으면 확정을 막는다 |
| 명세서마다 **공급자/공급받는자**가 같이 있어서 헷갈렸다 | 우리 가게 사업자번호를 알려 두면 **공급자(거래처)만** 골라 낸다 |
| 이게 식자재인지 소모품인지 **분류는 따로** 해야 했다 | 삼겹살·쌈장 → 원재료, 소주 → 주류, 숯·호일 → 소모품비처럼 **계정과목을 자동으로 붙인다** |
| 월말에 거래처별로 얼마 줘야 하는지 **다시 합산**해야 했다 | 외상 명세서는 **외상매입금**으로 분개되고, 거래처별·월별 합계가 자동으로 나온다 |
| 결국 필요한 건 **엑셀 파일**이었다 | 손으로 만들던 그 표를 **엑셀로 그대로** 내려받는다 (합계는 SUM 수식) |

**목표는 "찍는 것"과 "엑셀"사이에 있던 손 작업을 없애는 것**입니다.
다만 장부는 틀리면 안 되기 때문에, AI가 다 알아서 처리하게 두지 않고 **사람이 한 번 확인하고 확정하는 단계**를 일부러 남겼습니다.

## 주요 기능

1. **찍기** — 휴대폰 카메라로 바로 찍거나, 찍어 둔 사진 여러 장을 한 번에 업로드 (JPG·PNG·HEIC)
2. **AI 인식** — Claude 비전 모델이 사진에서 거래처, 사업자번호, 일자, 결제수단, 품목표(품목·규격·수량·단가·공급가액·세액), 합계를 구조화된 데이터로 추출
   - API 키가 없거나 호출이 실패하면 **Tesseract 한국어 OCR + 규칙 파서**로 자동 전환
3. **검토** — 사진과 폼을 나란히 놓고 수정. 금액 불일치·빈 칸·AI가 자신 없어 한 부분을 경고로 표시
4. **확정 = 회계 처리** — 확정하는 순간 복식부기 분개 생성 (차변·대변 합계 일치를 코드로 보장)
5. **장부·정리** — 월별 목록, 거래처별·계정과목별 합계, 분개장
6. **엑셀 내보내기** — `거래내역` · `품목상세` · `분개장` · `집계` 4개 시트

### 회계 처리 방식

매입 한 건(문서 한 장)은 이렇게 분개됩니다.

```
(차) 원재료(식자재)       273,000    ← 품목의 계정과목별로 나눠서
(차) 부가세대급금           1,300
    (대) 외상매입금                  274,300   ← 결제수단에 따라 달라짐
```

| 결제수단 | 대변 계정 |
| --- | --- |
| 현금 | 현금 |
| 카드 | 미지급금(카드) |
| 계좌이체 | 보통예금 |
| 외상 (월말 정산 명세서) | 외상매입금 (원재료) / 미지급금 (그 외) |

계정과목: `원재료(식자재)`, `원재료(주류·음료)`, `소모품비`, `수도광열비`, `복리후생비`, `지급수수료`, `수선비`, `기타비용`

## 실행 방법

### Docker로 실행 (권장)

```bash
cp .env.example .env          # 필요하면 ANTHROPIC_API_KEY, 우리 가게 사업자번호 입력
docker compose up --build
```

- 서비스 화면: http://localhost:8080
- API 문서(Swagger): http://localhost:8000/docs

> `ANTHROPIC_API_KEY`를 비워 둬도 동작합니다. 이때는 Tesseract OCR로 읽기 때문에 인식률이 낮고, 검토 단계에서 더 많이 고쳐야 합니다.

### 개발 모드 (코드 수정이 바로 반영)

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build
```

- 프론트엔드(Vite 핫 리로드): http://localhost:5173
- 백엔드(uvicorn --reload): http://localhost:8000

### 테스트

```bash
docker compose run --rm backend pytest -v
```

| 테스트 | 확인하는 것 |
| --- | --- |
| `test_core.py` | OCR 텍스트 파싱(공급자/공급받는자 구분, 표 머리글 오인 방지), 계정 분류, 금액 보정, 분개 대차 일치, 금액 불일치 시 확정 거부, 엑셀 시트·수식, 추출기 장애 시 대체 경로 |
| `test_claude_mapping.py` | Claude 응답 → 내부 데이터 변환, 허용 목록 밖 계정과목 보정, 잘못된 값 무시 |
| `test_api.py` | 업로드 → 수정 → 확정 → 집계 → 엑셀 → 확정 취소 → 삭제 전체 흐름 (가짜 추출기 사용) |

## API

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| `POST` | `/api/documents` | 사진 업로드(여러 장) → 자동 인식 후 '검토 필요'로 저장 |
| `GET` | `/api/documents` | 목록 (상태·종류·거래처·기간 필터) |
| `GET` | `/api/documents/{id}` | 상세 + 현재 기준 경고 + 분개 |
| `PUT` | `/api/documents/{id}` | 검토 내용 저장 (확정된 문서는 분개도 다시 생성) |
| `POST` | `/api/documents/{id}/confirm` | 확정 → 분개 생성 |
| `POST` | `/api/documents/{id}/unconfirm` | 확정 취소 → 분개 삭제 |
| `DELETE` | `/api/documents/{id}` | 문서·사진 삭제 |
| `GET` | `/api/summary` | 월별·거래처별·계정별 합계 |
| `GET` | `/api/journal` | 분개장 |
| `GET` | `/api/export/excel` | 엑셀 다운로드 (`include_pending=true`면 검토 전 문서 포함) |

## 설계하면서 고민한 점

- **AI를 믿되, 장부는 사람이 확정한다.** 인식 결과는 항상 '검토 필요' 상태로 들어오고, 사람이 확정해야 분개가 생깁니다. 금액이 맞지 않으면 확정 자체가 막힙니다.
- **추출기는 갈아 끼울 수 있게.** Claude와 Tesseract가 같은 `ExtractionResult`를 돌려주므로, 다른 OCR(예: CLOVA OCR)을 붙여도 나머지 코드는 그대로입니다. 주 추출기가 실패해도 사진은 저장되고 직접 입력할 수 있습니다.
- **AI 응답 형식을 강제한다.** 자유 텍스트 JSON 대신 툴 스키마(`tool_choice`)로 받아서 파싱 실패를 없애고, 계정과목은 정해진 목록 안에서만 고르게 했습니다. 목록 밖 값이 오면 규칙 분류기로 다시 분류합니다.
- **도메인 로직은 웹·DB와 분리.** 파싱·분류·분개·엑셀은 순수 함수라서 DB 없이 테스트됩니다.
- **엑셀은 "내가 쓰던 그 표"처럼.** 합계는 값이 아닌 `SUM` 수식으로 넣어 엑셀에서 행을 고쳐도 합계가 따라 바뀝니다.
